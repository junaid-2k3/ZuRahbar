02 • The Problem Commuter Pain Points

Navigating Zu Peshawar is Hard for Daily Riders

High network complexity coupled with fragmented, non-computable public information.

01 No Trip Planner

TransPeshawar provides static timetable tables but zero point-to-point journey planning. Riders must manually guess multi-bus transfers.

02 Fares Hidden in Urdu JPEGs

Fare tables exist only inside an Urdu image file on the website. Route leg distances are completely unpublished.

03 Missing & Conflicting Data

9 feeder routes have no published timetables; 3 routes have stop sequences unreadable on map images. Web pages contradict card prices (Rs. 300 vs Rs. 400).

04 • Architectural Core Design Philosophy

Why Standard LLMs Fail — The Deterministic Split

Preventing LLM transit hallucinations through strict division of responsibility.

❌ Pure RAG / Raw LLM Approach

LLMs cannot compute graph shortest paths, wait times, or distance fare bands.

  • Hallucinates non-existent bus transfers
  • Invents wrong fare prices
  • Ignores service operating hours
✅ ZuRehbar Engine Architecture
"The model decides WHICH tool to call and HOW to phrase the answer; the tools decide WHAT IS TRUE."
  • NetworkX Graph: Shortest-path routing & platforms
  • Distance Engine: 9-band exact fare math
  • Qdrant Hybrid Search: BM25 + Qwen dense vectors

06 • Graph Engine Transit Routing Logic

Solving Transit Math: Route-Stop Graph Modeling

Why standard station graphs fail and how route-stop nodes model wait friction.

Route-Stop Graph Model

Nodes modeled as stop:R:D:S (Route R, Direction D, Station S).

Boarding Weight = (Headway / 2) + 90s Transfer Penalty Riding Weight = Leg Travel Time (sec) Alighting Weight= 0

Shortest path pathfinding inherently favors a single-bus ride ("one-seat preference") unless a transfer saves genuine travel time.

Distance Interpolation & Fares

Zu charges distance-based fares across 9 bands (Rs. 30 to Rs. 70).

Leg Distance (km) = Total Length * (Leg Time / Total Time)

Distance is interpolated proportionally from travel time share. Results carry an explicit is_estimate: true flag.

07 • Data Engineering Robust Data Ingestion

Robust Ingestion from Imperfect Web Sources

Overcoming broken SSL, Urdu image data, and official dataset contradictions.

Custom HTTP Client

Handles TransPeshawar's broken TLS certificate chain safely in http.py with 1 req/s rate limiting and disk caching.

AI Vision Tiling Pipeline

Tiles high-resolution Urdu fare matrices into spatial grids, extracting data into data/review/*.json with provenance stamps.

Honest Anomaly Report

Contradictions (e.g. card prices, route timeline vs timetable mismatches) are logged in dataset_report.json rather than hidden.

08 • Vector Index Knowledge Retrieval

Precision Knowledge Retrieval for Non-Trip Queries

Qdrant dense + BM25 sparse hybrid vector search over transit rules and station facts.

Dense Embedding Model

Uses Qwen/Qwen3-Embedding-0.6B (1024-dim). Captures multilingual intent across English, Urdu, and Pashto.

BM25 Sparse Vector Anchoring

Dense models blur rare proper nouns like "Hashtnagri". BM25 sparse vectors anchor station names with 100% precision.

Server-Side RRF (Reciprocal Rank Fusion)

Qdrant merges dense semantic search hits with BM25 sparse keyword rankings, returning grounded policy snippets for Qwen to phrase.
